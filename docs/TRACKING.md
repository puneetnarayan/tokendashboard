# token-dashboard — Project Tracking

**Single source of truth: [Token Dashboard Roadmap](https://github.com/users/NewAiCoder/projects/5) + [Issues](https://github.com/NewAiCoder/token-dashboard/issues).**
Not Trello, not Jira, not scratchpads, not `.md` worklogs. One surface — a kanban board backed by issues.

## The board

5-column kanban at [https://github.com/users/NewAiCoder/projects/5](https://github.com/users/NewAiCoder/projects/5):

| Column | Means | Populated by |
|---|---|---|
| **Backlog** | Open, not yet prioritized for the current milestone | Default for new p2/p3 issues |
| **Todo** | Picked for the current milestone — the drive-next queue | p0/p1 issues land here |
| **In Progress** | Currently being worked on. Move yourself here when claiming work. | Manual board move |
| **In Review** | Code shipped, awaiting verify / human test | `needs-verify` labels + `(refs #N)` commits |
| **Done** | Closed — completed and verified | `(closes #N)` commits + manually-closed issues |

## Workflow

### At session start (auto)

A SessionStart hook (`~/.claude/hooks/session-start-token-dashboard.sh`) fires when Claude opens a session inside this repo. It queries the board and prints column counts + In Progress + Todo + In Review items, so you don't have to ask "what's the backlog."

### Picking work

1. Open the [board](https://github.com/users/NewAiCoder/projects/5).
2. Drag a card from **Todo** (or **Backlog**) into **In Progress**. That's your "claim."
3. (Optional) Add yourself as Assignee.
4. Add comments on the issue as you discover things — keeps the audit trail.

### During work

- **New bug found mid-session:** `gh issue create -t "area: short title" -b "..." --label "bug,area:X,p2"`. New issues land in **Backlog** by default.
- Reference related issues in comments so timelines cross-link.

### When an issue is filed — auto-add to board

A PostToolUse hook (`~/.claude/hooks/post-bash-token-dashboard-add-issue-to-project.sh`) catches every `gh issue create` against this repo and immediately adds the new issue to the project board. Without this, an issue can be filed AND closed in the same session (via `(closes #N)`) and never appear on the board — the link-commits hook only moves items already there.

### At commit time — auto-link via message

A PostToolUse hook (`~/.claude/hooks/post-bash-token-dashboard-link-commits.sh`) parses commit messages and acts:

| Pattern in commit message | Effect |
|---|---|
| `closes #N` / `fixes #N` / `resolves #N` | Comment on issue with SHA + subject. Close issue. Move card to **Done**. |
| `refs #N` / `references #N` | Comment on issue with SHA + subject. Move card to **In Review**. |
| Both for the same issue | Closing wins. |

Idempotent via short-SHA marker — the same commit never double-comments.

Examples:
```
fix(audio): trim mux to video duration (closes #1)
feat(video): write display_time PTS sidecar (refs #7)
chore(test): unstale fixtures (closes #15)
```

### At session end

Scratchpads are session-only. If a scratchpad accumulated long-term backlog content during the session, drain it into issues before closing the session.

## Label scheme

### Areas (which subsystem)
- `area:scanner`
- `area:api`
- `area:ui`
- `area:cli`
- `area:tests`
- `area:docs`
- `area:tech-debt`


### Priorities (drives Todo placement)
- `p0` — drop everything (red)
- `p1` — soon, this milestone (orange) — auto-lands in **Todo**
- `p2` — planned (yellow) — auto-lands in **Backlog**
- `p3` — later / nice to have (light blue) — auto-lands in **Backlog**

### Status (drives In Review placement)
- `needs-verify` — code shipped, awaiting runtime test
- `needs-repro` — awaiting reproduction before action
- `blocked` — blocked on upstream / another issue

### Type
- `bug` — defect
- `feat` — new feature (alias of `enhancement`)
- `chore` — maintenance, build, deps

## Triage

1. **p0 first.** Drops everything else.
2. **p1 next.** Core value-prop blockers > quality > new features > polish.
3. **p2 / p3** batched between p1 cycles based on adjacency.
4. **In Review** items get tested at the start of any session where verification is possible.
